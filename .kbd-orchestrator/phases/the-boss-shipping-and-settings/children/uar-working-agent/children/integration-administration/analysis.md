Managed images use the same source. Parser errors must not echo secrets or raw TOML. This closes an implementation dependency absent from the provisional plan.
9. Preserve feature boundaries and generated outputs. Renderer and main have 13 locale catalogs each; existing strings can be reused, all new statuses/navigation/errors require complete translations. New document fields live in existing preference storage; SQL migration only if an actual table changes.

## Issue #296 — reuse run-owned transport; close the remote trust gap

The issue proposes several possible remedies. Its substantive requirement is per-run human/tenant authority reaching the downstream MCP server. The inspected code already isolates loopback run headers in a dedicated binding cache. Adopt that design (cand-014), extended through an explicit trusted-host admission path. Do not recreate a transport per tool call and do not mutate a process-global header map.

- Add optional static header/secret-reference configuration for RemoteHttp, resolved into private frozen binding inputs. Preserve existing url/env configurations. Static headers prove a service identity only.
- General remote grants refer to a registered destination and arrive from a verified host/BFF authorized to delegate that principal. Derive tenant/user from verified authentication/delegation, not model arguments or an arbitrary x-tenant header. Reuse UAR's existing issuer/audience verifier and principal types, adding a trusted delegation capability and destination policy where absent. Keep the Boss sidecar's loopback host-launch guard; remote outbound access does not authorize a remote listener or weaken incoming authentication.
- Use a downstream-specific token issued for the MCP resource, separate from the UAR API/launch token. A trusted BFF may supply this credential through authenticated run admission; UAR does not pretend it can validate opaque token claims. The configured issuer/downstream verifier enforces audience, expiry and scopes. Retain host-authorized expiry and credential revision in private run resource metadata; keep secret bytes out of catalog hashes, JSON, checkpoints and logs.
- Use one isolated transport/session per run and selected server credential revision, reused for that run's calls. Transport configuration includes identity on initialization, discovery, calls, SSE/reconnect and cleanup. Cache identity includes owner, run, destination and non-secret credential revision. Static and run headers merge only by explicit declaration; ambiguous duplicates and transport-owned headers are rejected. Never implicitly copy inbound headers. Preserve destination scheme/address policy, no redirect credential forwarding, and no ambient proxy leaks.
- Expiry or revocation stops new calls with auth_required. A trusted host may reattach a fresh same-owner grant at a safe step/continuation boundary; invalidate the old binding and establish a new session, then re-project tools. No model-controlled credential refresh, no silent widening, and no automatic replay of an uncertain mutating call. A missing renewal source is an actionable auth-required result, not fallback to another tenant or global service key. Bound cleanup and revoke run credentials on cancel/end.
- Local delegated children receive narrowed frozen bindings; remote peers obtain their own authenticated root grants. Catalog MCP references select from the authorized host universe, never embed live credentials or override its authority.

This supplies a run-specific identity on every outbound request. Arbitrary identity changes within one run are deliberately rejected; per-call authorization can narrow the effective grant but cannot switch tenant. A custom dynamic rmcp transport is unnecessary for this requirement and is rejected (cand-015). If future callers require a different identity per call, that is a distinct authorization contract, not mutable ambient state.

SDK evidence: UAR pins rmcp =3.1.2; its installed StreamableHttpClientTransportConfig has auth_header/custom_headers and the worker copies those into request/reconnect/cleanup. Context7 current documentation confirms the general API but is not substituted for pinned source. No automatic bump to Compass's =3.4.0. Firecrawl located the official MCP security guidance; identity/audience separation is consistent with its token-passthrough prohibition: https://modelcontextprotocol.io/docs/2026-07-28/tutorials/security/security_best_practices . Review claims are source-based; actual concurrency, reconnect and expiry behavior awaits the completed integration gate.
