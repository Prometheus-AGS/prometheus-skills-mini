# Round 1 resolution

1. **Governance argument finding — rejected after call-path inspection.** `RootApprovalChannel::request` places its `arguments_json` parameter directly into `ToolCallApprovalRequired`, which is a renderer-bound display event. `GovernanceEngine::tool_decision` accepts agent identity, tool identity and the approval-required flag; it has no argument-policy input. Supplying `validated_arguments` at this call site would disclose raw write contents and credentials to the renderer, violating task 2.4. The frozen validated value remains in `PreparedToolInvocation` and the Boss exact admission record, where it is compared against the actual managed `tools/call` before claim. The safe projection is therefore retained at this display boundary.
2. **Production bridge gate — fixed.** Gate A1 now creates `createUarHostMcpBridge`, authenticates through its generated bearer token, connects an MCP client through the mounted Streamable HTTP server, and observes an actual tool effect. Prepare, resolve, namespaced metadata, atomic claim, replay/mismatch/identity/batch/version rejection and bridge cleanup all run through production bridge code.
3. **Localized stale-approval error — fixed.** The runtime error now carries the stable message key `uar_approval_stale`, which `ErrorBlock` resolves as `error.uar_approval_stale`. All thirteen existing locales contain translated actionable text.
