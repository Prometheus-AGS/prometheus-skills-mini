## Why

The existing UAR plan delays the first installed user experience behind a long backend-only sequence and contains superseded technical instructions. We need one researched delivery contract that preserves the full scope while shipping demonstrable functionality and overlapping acceptance with succeeding development.

## What Changes

- Create a planning-only KBD child, with repository evidence and an independent adversarial review.
- Replace backend-first sequencing with complete application phases: working agent, interactive workflows, knowledge/storage, adaptive intelligence, and remaining platforms.
- Define host/runtime ownership, capability contracts, release isolation, and integration-only phase gates.
- Preserve existing UAR work and all approved features; identify every superseded instruction explicitly.
- Prepare a GPT-5.6-sol execution handoff, gated on operator reflection and approval.

## Capabilities

### New Capabilities
- `uar-phased-delivery`: Defines the cross-repository delivery contract and acceptance boundaries for UAR in The Boss.

### Modified Capabilities
None. Existing UAR OpenSpec changes are mapped to delivery phases without being rewritten in this planning-only change.

## Impact

This change writes planning/process documents only in mini. It specifies future UAR Rust API/runtime and The Boss Electron/React integration work, native release packaging, and publication. No application code, dependencies, tests, builds, current installers, or UAR WIP are changed in this phase.
