# Proposed child scope amendment — pending operator handover

Analyze found a static production contract contradiction needed for native discovery: Boss host finish requires claimed, but its consuming claim currently exists only at mounted MCP dispatch. UAR executes native search locally and then calls the same host terminal path. The controlled provider also lacks discovery continuation.

The current goals allow a correction to the provider or production path, but scope.json lists only scripts/gates and child artifact write roots. No new product root has been authorized or edited during Analyze.

Proposed amendment for reviewed Spec/Plan, before Execute:

1. Replace “Establish the cause before correcting it” with “Establish the inspected contract failures and retain the unknown historical runtime12 cause; require finite source-bound branch evidence in the completed correction gate to establish or falsify applicability.”
2. Add native execution authority and consuming claim/terminal integration to the child requirements, alongside the provider correction.
3. Expand potential product ownership only to the required UAR admission/lifecycle/dispatcher contracts and Boss UarHostToolAdmission plus owned callers. Spec/Plan must list actual files; this proposal is not broad repository write permission.
4. Require fresh affected UAR and development desktop payloads when production source changes; retain exact source/binary binding. This is development verification, not release/signing/package bypass.
5. Retain all exclusions and stage stops; no production implementation until reviewed Spec and Plan handovers.

Default interface for Spec to adopt or reject (proposed, not implemented): executionKind enum runtime-native/host-mcp, derived from UAR's resolved ToolSource and bound into prepared authority and receipt equality. Use a strict owned-caller admission wire cutover, proposed version2, with a distinct consuming native-claim operation under that version. Reuse existing invocationId/admissionId and persistence systems; no new store or daemon. Preserve nonconsuming MCP claim revalidation and the receiver's consuming claim.

Order: current admission/approval → current revalidation/Cedar/lease/budget/cancellation checks → existing durable UAR claim → host consuming native claim with durable lifecycle evidence → native dispatch → claimed-only terminal receipt. Native dispatch requires positive host acknowledgment. An unconsumed failed claim is cancelled/invalidated; uncertain consumption/acknowledgment retains unknown and reconciliation rather than repeating an effect. Spec must settle exact cleanup semantics and all owned callers before implementation.

Accepting the Spec handover authorizes drafting these bounded requirements and reconciling authored goals/scope; it does not authorize Execute or close any parent gate.
