## Credential inputs and ordinary projection seams

1. Request provider keys/base URLs use SecretString, redacted Debug, no Serialize. credentials.rs211–217 captures all request credential keys and URLs into RunSecretScrubber. routes.rs312 and364 extend the request scrubber from provider and MCP inputs. The emitter receives a clone in manager; run request default is empty.
2. Direct-loopback MCP captures full URL plus header values (host/mcp.rs209–245); trusted grants capture expanded URL and grant overlay header values (317–318). Destination-configured resolved secret-ref headers are parsed by RunHttpHeaders::from_configuration but are NOT added to that host scrubber. The plain Bearer token stripped from the Authorization value at runtime.rs95–102 is also not independently captured by host/mcp.rs. Echoing only the token can evade matching of the full header value.
3. Runtime headers are private/redacted Debug. Config header secret refs resolve against the immutable request env. Stdio declared env resolves from that same snapshot. Neither all parent env values nor arbitrary documents should become a global secret dictionary; capture only values actually granted to the selected connection plus the run's resolved provider/login credentials.
4. host/mod.rs38–72 scrubber currently performs sequential exact string and standard-base64 replacement, no JSON traversal, non-secret indicator or fragment state. Overlapping secrets can partially replace a longer secret before it matches; independent stream fragments can split a known value. This is finite known-value protection, not DLP or detection of arbitrary encodings/secrets.
5. Projected connection and handshake errors are already converted to static McpBindingError categories (registry731–846; runtime826–862); lifecycle events carry typed reason/opaque IDs rather than raw token-bearing diagnostics. Keep these. Legacy registry startup tools/list/reconnect warning branches include raw SDK errors (registry1267,1300,2450); provider error log paths need their own early protection.
6. RunEventEmitter::emit (manager277–302) scrubs ONLY runtime Error.message before EventHistory.record. ToolStart/input, ToolDelta, ToolEnd/output, text/thinking/reasoning deltas, artifact/state payloads are outside this matching. Sanitizing only here is too late for model/history/canonical storage and cannot repair text already emitted in earlier fragments.
7. Orchestrator::execute_direct_tool (521–614) passes native/MCP result or error through preserve_canonical_tool_result/preserve_terminal_tool_failure. The first ordinary persistence is preserve_canonical_tool_result871–908, which currently passes typed Value and raw_segments directly to CanonicalToolReceipt::acquire_with_segments then save. This helper returns raw Value unchanged when no store exists. It is the mandatory shared result sanitation seam BEFORE its early no-store return.
8. Graph MCP uses the same canonical helper (1005–1126), then ToolEnd and graph output. Main sequential and parallel tool branches ultimately produce canonical/display strings and ToolResult; sequential branch2736–2762 writes both model history arrays. Manager additionally records incoming normalized ToolResult into session/dialogue BEFORE the runtime emitter (around6239–6248). Therefore emitter-only sanitation cannot meet model/persistence coverage.
9. CanonicalRawSegment stores byte-exact base64 plus byte_len/sha256 (persistence/agent_threads.rs39–99), and native result acquisition supplies these independently of typed_value. Redacting only JSON strings leaves retained raw bytes intact. Parent04's secret exclusion conflicts with preserving secret-bearing raw receipts as lossless originals: proposed contract is to acquire canonical receipts FROM already-projected output; reconstruct retained segment bytes/digests consistently and report only a non-secret redaction indication. Never change bytes while retaining old digest/length, silently label raw original content preserved, or add a secret archive. Existing incomplete/unretained segment semantics must remain truthful. Driver must accept this semantic clarification before that production slice.
10. Main model driver stream (orchestrator2119–2194) accumulates assistant_text and executable tool arguments before yielding; ToolCallDelta is split JSON text. Keep original validated arguments for authorized transport/approval digest. Ordinary event/history copies must be projected separately. A stream projector must retain a bounded matching tail per logical text/call stream, flush at correct terminal/order boundaries and cannot leak a split prefix on cancellation. Do not run a generic string replacement over serialized JSON and reparse it.
11. Provider_log_summary/provider_failure (orchestrator826 onward) safely categorize settings-profile team errors but ordinary errors retain raw text; retry/fallback logs use that summary, non-streaming error path2832 logs raw error. Anthropic driver351–365 receives remote error text and390 directly warns on SSE error before the orchestrator; this is an earlier log sink. Existing request scrubber cannot sanitize a log already emitted here.
12. Manager apply_credential_layer505 captures resolved stored keys, and model capture around4409–4588 receives explicit/config/fallback keys; request scrubber only covers request-provided keys. RunModelBindings::capture (bindings200–308) can construct primary and fallback drivers and logs fallback construction errors291. There must be a captured projection contribution from actual resolved primary/fallback configs BEFORE logs/constructors; do not rediscover mutable process env later. A supplied opaque driver cannot reveal its credential through this API; caller-owned capture or static driver errors are required, not a claim that UAR knows its key.
13. Login/sidecar bearer is intentionally not in UserContext. It is consumed by middleware/SidecarGuard and not forwarded to MCP. The selected run scrubber does not currently receive it. Thus arbitrary deliberate login-token echo cannot honestly be claimed covered by existing run matching. The Boss holds its launch token and has a separate projector; complete UAR login-canary coverage needs an explicitly accepted request-local secret contribution at authenticated ingress, never changing proof semantics or forwarding it as resource authority.

## Completion boundary and uncomfortable limits

This inventory is a proposal, not reproduced behavior or a bug-fix completion claim. Source already contains numerous lifecycle safeguards, but static reading cannot prove cancellation races, actual effect counts, stream timing, receiver authorization or Windows execution. Root has released UAR02 source; exact projection claims still await acceptance. The uncomfortable point is that adding a smarter emitter scrubber alone could make SSE look safe while canonical receipts and next model requests still contain credentials. Ordinary persistence and model copies must be covered first, and login/ambient-provider/raw-segment semantics cannot be omitted from the completion denominator.

No unrequested product code or security guard was added. Proposed hardening traces only to actual host-auth ingress, configured credential transport, untrusted tool/provider output, child stderr, ordinary persistence and model boundaries. Verification was intentionally not run. Common fixture acceptance will not close D0, C05/shipping, external receiver/custody, installed-app or cross-platform claims.
