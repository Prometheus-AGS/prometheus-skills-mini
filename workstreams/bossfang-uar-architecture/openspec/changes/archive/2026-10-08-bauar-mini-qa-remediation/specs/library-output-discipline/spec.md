# Spec Delta

## Purpose

Upholds the rule that library modules never print, extending it to the executable fixtures library tests generate: fixture program output is constructed at the edge with byte-identical content instead of console output calls.

## ADDED Requirements

### Requirement: Generated fixture programs use edge-output construction

The executable fixture programs generated by the distribution package-builder and learning identity tests SHALL construct their stdout output without `console.log` or `console.debug`, preserving exact byte content including JSON structure and terminating newlines.

#### Scenario: Identity resolver consumes identical output

- **WHEN** the identity fixture program runs and emits its single JSON status line
- **THEN** the resolver parses it exactly as before, with the same newline-terminated bytes

#### Scenario: Packaged fixture payloads remain valid stand-ins

- **WHEN** the package-builder tests materialize payloads containing the reconstructed fixture files
- **THEN** payload generation, copy and digest comparisons behave as before and the tests pass

### Requirement: The output constraint passes without gate changes

The `no-console-log-in-lib` constraint SHALL pass with its existing check expression unchanged — the fixtures change, not the gate. No production library module SHALL gain console output as part of this change.

#### Scenario: Constraint clean, gate untouched

- **WHEN** the `no-console-log-in-lib` constraint is evaluated after the repair
- **THEN** zero matches are reported and the check expression is byte-identical to its pre-repair form
