# Proposal

## Why

A built bundle, supporting test binary and historical fixture pass establish different claims. Local acceptance needs a finite coordinator and auditable source-bound receipts that cannot convert missing checks, cancelled scope or stale artifacts into readiness.

## What Changes

- Define a Node LTS coordinator, versioned configuration/receipt schemas and a fixed scenario inventory for the three siblings.
- Bind the actual package and bundled sidecar to sources, build profiles and completed production before one consolidated local gate.
- Retain stale-source/archive/public-mode negative controls, finite eligible regression, secret-safe evidence, scoped formatting and cumulative completed-product review.
- Produce an explicit local readiness verdict and release-scope/owner disposition without signing, installation or publication.

## Capabilities

### New Capabilities

- `local-acceptance-evidence`: source-bound coordination and distinct outcomes for local production-path acceptance, supporting regression, review and wider release scope. Existing bundle-provenance covers artifact production; it is retained unchanged.

### Modified Capabilities

None.

## Impact

scope: phase `acceptance/local-release-acceptance.mjs`, `acceptance/lib/{inputs,processes,receipts,stages}.mjs`, `acceptance/{config,receipt}.schema.json`, `acceptance/candidate-inputs.json`, `acceptance/review-paths.json`, `evidence/execute/**`, `review/execute/**`, `release-readiness.md`. These proposed files are not existing commands. Change 03 owns all common coordination; change 02's two inventory files are inputs and must not be rewritten by this owner.

No new runtime/dependency/service; no product behavior changes. Source artifacts and caches remain retained. Local unsigned darwin-arm64 is the proposed target ratified by Plan approval; broader scopes are explicitly deferred to the operator, not hidden blockers on this target.
